# Koreo Milestone 5 execution handoff — manual project persistence

**Status:** Approved
**Approval:** Owner response in GitHub issue #33 on 2026-10-12
**Authority:** Sole execution contract for the first Milestone 5 slice

## Outcome

Let users atomically save and safely reopen the complete project they authored,
including optional audio, without losing exact beat values or replacing current
work with invalid input.

## Binding behavior

- The native `.kro` file is one portable ZIP container containing
  `project.json`, an optional derived waveform cache, and, when selected, the
  original audio under `audio/`.
- Format version `0.1` is explicitly pre-1.0. Exact values use integer
  numerator/denominator pairs. IDs and complete authoritative project state
  round-trip unchanged.
- The main window provides a File menu, Open/Save toolbar actions, Save As,
  Ctrl+O, and Ctrl+S. First Save chooses a path; later Save reuses it.
- The title shows `*` while dirty. Opening or closing dirty work offers Save,
  Discard, and Cancel.
- Saving writes a temporary sibling archive, flushes it, and atomically
  replaces the destination. Failure retains the prior file and dirty state.
- Loading verifies the archive, version, complete model, and declared embedded
  audio before replacing current state. Invalid input leaves current work
  untouched.
- Embedded audio extracts into an application-owned temporary directory for
  playback and is cleaned at exit.
- Users are responsible for having the rights to store or share embedded art.
- Periodic recovery snapshots, retention, audio replacement, project
  duplication, and stable post-1.0 migrations remain deferred.

## Validation

- Exact project/calibration and embedded audio round-trip tests.
- Projects without audio round-trip.
- Unsupported versions and missing/corrupt content fail safely.
- A failed save cannot alter the last valid destination.
- GUI smoke coverage verifies dirty state, title marker, actions, and saving.
- Run pytest, Black, mypy, and `uv build`.
